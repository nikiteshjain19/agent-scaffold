# D-47 — 2026-10-05 — Release `0.2.0` now, as a minor release, ahead of #4's procedure

- **Decision:** Release `0.2.0` of the `hivion` plugin now, as a minor release under the version
  scheme #4 proposes. A release pull request may land before #4 writes the release procedure into
  `PROJECT.md`. That pull request changes only the manifest's `version` value, `CHANGELOG.md` and
  this entry. The `v0.2.0` tag and the GitHub Releases for `v0.1.0` and `v0.2.0` are published
  after the merge, by the owner or by an agent holding the owner's explicit go-ahead.
- **Context:** #47. The owner approved this on 2026-10-05 ("let's uh, release zero point two zero
  now."), on a proposal that read: "Release 0.2.0 now — one small issue (via issue-writer) for a
  release PR: bump plugin.json to 0.2.0, add a CHANGELOG.md with this release's notes — then tag
  v0.2.0 and publish a GitHub Release after it merges. #4's full procedure still lands later."

  **Why a release is needed at all.** Claude Code takes an installed plugin's version from the
  manifest's `version` field first. Its plugin manifest reference says that setting it "pins the
  plugin to that version until you change it", and its plugin loading reference says such a
  manifest "keeps every user on the cached copy until its author changes the string, however many
  commits they push". The manifest has read `0.1.0` since the `v0.1.0` tag, and sixteen pull
  requests have merged since then. No installed copy has received any of them, including the move
  of the plugin root to `plugins/hivion/` (D-48), which only takes effect for a consumer once the
  version changes.

  **Why minor, not major.** #4 proposes patch for wording, minor for a new skill or a new rule, and
  major for a change that breaks a consuming repository. Its examples of a break are renaming the
  plugin, renaming a skill, and renaming a `PROJECT.md` section the skills read by name. None of
  them happened since `v0.1.0`:

  | Breaking shape (#4) | Since `v0.1.0` |
  | --- | --- |
  | Rename the plugin | No. `name` is `hivion` in the plugin manifest and in the marketplace. |
  | Rename a skill | No. All seven `v0.1.0` skills still exist, moved unchanged under `plugins/hivion/skills/` by #48. `project-onboard` was added. |
  | Rename a `PROJECT.md` section the skills read by name | No. "Toolchain", "Build / lint / test commands", "Merge gate" and "Parallelism" are unchanged. |

  The repository gained a new skill (`project-onboard`) and new rules, which is the minor case.
  The three merges after the issue was filed were checked against the same shapes. PR #49 (#45)
  changed only this repository's `PROJECT.md` and logged D-45. PR #50 (#46) added a `CLAUDE.md`
  §7 rule and re-marked citations in the skills, and renamed no heading or skill. PR #52 (#48)
  moved the plugin root, and D-48 records its own verdict that it is not breaking: the names are
  unchanged, the skills still load as `hivion:<name>`, and the commands a consumer types are the
  same.

  Two changes come close, and neither is breaking. **The verdict shape (D-5):** the `pr-reviewer`
  skill's verdict block now carries `HEAD`, `FINDINGS` and `ADVISORY`, and the `cycle-manager`
  skill's C2 and C3 contracts changed to match. The block passes between skills inside one
  session. Its producer and both readers — C2 and C3 in the `cycle-manager` skill, and A RELAYED
  VERDICT in the `pr-merge-loop` skill — ship in the same plugin version, and no file or
  `PROJECT.md` section in a consuming repository carries it. Before D-5 the two shapes did not
  match, so nothing depended on the old shape working. **The `CLAUDE.md` §0 heading** changed from
  "New Project Bootstrap" to "Project Bootstrap" (D-16). That is a `CLAUDE.md` heading, not a
  `PROJECT.md` section, and the skills cite it as §0.

  **Why not wait for #4.** #4's comment of 2026-10-04 put the procedure last in its own sequence,
  and every day without a bump is a day installed copies receive nothing. This release therefore
  runs ahead of the procedure, by the owner's choice. #4 extends `CHANGELOG.md` rather than
  creating it, and keeps the version scheme, the bump rule and the `PROJECT.md` "Releases" section.

  **How the changelog was sorted.** Each entry comes from one squash merge in
  `git log v0.1.0..main`, and a merge appears only if a consumer receives it. Five merges changed
  only this repository's own project record and are left out: PR #24 (#3), PR #25 (#13), PR #32
  (#29), PR #38 (#36) and PR #40 (#35); PR #49 (#45) joins them. PR #50 (#46) is listed under
  Added, because it adds a `CLAUDE.md` rule and the skills now write citations that only that rule
  explains, so the upgrade note names it beside the three rules the issue listed. PR #52 (#48) is
  listed under Fixed, because #48 framed the root install as a defect ("Stop installing the hivion
  plugin from the repository root"), and the pull request typed its commits `fix`.

  **No relation.** `CLAUDE.md` §7 asks whether an earlier decision still binds. No earlier entry
  decided how a release is cut, and #4 is an issue, not a decision. So this entry has no
  `Supersedes` and no `Corrects`, and edits no earlier entry. D-48 named #47 as the owner of the
  bump, and stays true.
- **Affects:** `plugins/hivion/.claude-plugin/plugin.json` (`version`); `CHANGELOG.md`; the
  `v0.1.0` and `v0.2.0` tags and their GitHub Releases; #4, which extends `CHANGELOG.md` rather
  than creating it; #47.
