# D-5 — 2026-10-05 — The reviewer's verdict carries `HEAD` and a `FINDINGS` block, and C2 and C3 change to match

- **Decision:** The `pr-reviewer` skill's verdict block now opens with the five fields the
  `cycle-manager` skill's C2 contract names, spelled and laid out as C2 lays them out: `VERDICT`,
  `PR`, `HEAD`, `INDEPENDENCE`, `FINDINGS`, followed by `ADVISORY`. The reviewer records the head
  commit SHA from the host as step 1 of its INDEPENDENCE phase, never from its invocation, and
  writes it into `HEAD`. Its branch-point and clean-worktree steps use that SHA, so `HEAD` names the
  commit it actually tested. `FINDINGS` stands alone on its line, and the block is every indented
  line beneath it down to the `ADVISORY` line: the pre-merge checks, the escalation conditions, the
  local check run and the reason. `ADVISORY` stays outside that block. `PR` carries the number only.
  C2 changes in three ways: `FINDINGS` becomes a block rather than a one-line value, an `ADVISORY`
  field is added, and the contract now says the `pr-reviewer` skill's RETURN THE VERDICT section
  owns the shape. C3 changes in one: it relays every indented line beneath `FINDINGS`, and never
  `ADVISORY`. C1, C4, C5, C6, C7 and C8 are unchanged.
- **Context:** #5, from an audit on 2026-09-18. C2 expected `VERDICT / PR / HEAD / INDEPENDENCE /
  FINDINGS`, but the reviewer returned `VERDICT / PR / INDEPENDENCE / PRE-MERGE CHECKS / ESCALATION
  CONDITIONS / LOCAL CHECK RUN / REASON / ADVISORY`. There was no `HEAD` field, so the manager's rule
  that voids a verdict whose `HEAD` no longer matches the pull request either looped or discarded
  every verdict, and the auto tier was unreachable through the manager. C3 relayed "the FINDINGS
  block from C2", which did not exist. Real runs on 2026-10-04 and 2026-10-05 confirmed it: the
  caller read the head SHA out of the `INDEPENDENCE` line and relayed everything after it as
  findings, which works only while a caller improvises the same way every time. Neither side could
  fix it alone, because the manager may never edit a verdict and C1 tells the reviewer to return its
  block unchanged.

  **Why the reviewer moved to C2, and not C2 to the reviewer.** The issue offered both. Renaming C2
  and C3 to the reviewer's real fields would still have needed a `HEAD` field in the reviewer, so it
  saved nothing on that side. It would also have left the `pr-merge-loop` skill's A RELAYED VERDICT
  section describing a block nobody produces, since that section copies C2's five fields and voids
  a verdict on its `HEAD`. Moving the reviewer keeps every field name both consumers already read.
  For the same reason the reviewer adopts C2's column layout and drops its colons, and `PR` drops
  the title and author: the three copies of the block then agree literally, and a caller can find a
  field by the word that starts its line.

  **Why the SHA is recorded in the INDEPENDENCE phase rather than in GATHER.** The issue asks for the
  SHA to be recorded "in its own phase". A verdict can stop in the INDEPENDENCE phase or in CONFIG,
  before GATHER runs, and that verdict needs a `HEAD` too. Recording the SHA first means every
  verdict, early or full, names its commit. Reading it from the host rather than from C1 mirrors the
  `pr-merge-loop` skill's own rule for a relayed verdict: the caller's copy is the claim being
  checked. If the head moves while the reviewer works, the verdict names the commit it started from,
  and the caller voids it; the reviewer does not need to detect the move.

  **Why `ADVISORY` stays outside `FINDINGS`.** The advisory notes exist because the owner left the
  house style unenforced (D-29). C3 hands `FINDINGS` to a repairer verbatim. A note inside that
  block would reach an agent whose job is to change the branch, which is enforcement under another
  name. It would also feed C8 predicate 3, which stops a loop when the same finding survives two
  rounds, so a style note nobody is required to fix could stop a loop. Keeping the field separate,
  and naming it in C2 so the contract describes the whole block, closes both.

  **Why this is a decision.** The `cycle-manager` skill says its contracts are frozen and that
  changing one is a decision (`CLAUDE.md` §7), because the skills it composes build against them.
  This entry is that record, so the owner approves the C2 and C3 change knowingly, with the pull
  request that makes it.
- **Affects:** the `pr-reviewer` skill (the machine-readable property, §0 INDEPENDENCE steps 1–3 and
  the paragraph after them, §2 GATHER step 7, §3 step 2, §7 RETURN THE VERDICT, the quality bar);
  the `cycle-manager` skill (C2, C3); the `pr-merge-loop` skill's A RELAYED VERDICT section, whose
  copy of the block shows `FINDINGS` as a one-line value and has no `ADVISORY` line — outside #5's
  footprint, so left for a follow-up; #5; #20, which reads `HEAD` to stop the void-verdict loop.
