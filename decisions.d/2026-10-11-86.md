# D-86 — 2026-10-11 — The `project-onboard` interview carries nothing read from the repository or tracker

- **Decision:** The `project-onboard` skill's interview carries nothing from the repository or the
  tracker. The output of `CLAUDE.md` §0's routing test is precondition evidence only: its path list
  and its open-issue count choose the path, and nothing else. The open issues are counted, never
  read, before the interview. The interview asks only the questions `CLAUDE.md` §0 and the skill
  list — §0's seven topics, the skill's present-tense changes and its four adoption questions — and
  illustrates none of them with a file, feature, defect, service, issue, pull request, label or
  person the owner has not named first. An example, where one helps, comes from §0's own text.
  Adoption question 1 is asked without listing the open pull requests and branches; the survey
  lists them.
- **Context:** #86. The owner reported on 2026-10-10 an onboarding run on another repository whose
  interview quoted what the preconditions had printed: topic 4 named the open issues and an open
  pull request by number and proposed sequencing examples built from their titles, and topic 5
  named a privacy page, the markets it serves and a list of services whose secrets it expected. It
  also asked about deadlines, which §0 does not list. The skill's text did not forbid any of it:
  PRECONDITIONS ran a routing test that prints every path in the history and counts the tracker's
  open issues, but never said that output was evidence for routing only; INTERVIEW said to cover
  the §0 topics but forbade neither extra questions nor examples; and the first HARD RULE forbade
  reading code before the interview, not quoting what the preconditions had already printed.

  **Why this is a correction to D-15 and not a new rule.** D-15's interview-first order exists so
  the owner states what they want before the code can shape the question. That order protects
  nothing if the questions carry the code anyway. A question that names what the repository holds
  asks the owner to confirm the repository, and a claim primed that way is exactly the claim the
  survey can no longer test. Closing the leak restores what D-15 already promised; it does not add
  a new guarantee.

  **What was left alone.** The owner chose to fix the leak only, and to keep §0's seven topics as
  the question set rather than write a separate set for existing projects. `CLAUDE.md` §0's routing
  test stays as written, and the skill still cites it rather than restating it (D-16). The survey,
  the reconciliation and the WRITE phase are unchanged.

  **Why `Corrects`, not `Supersedes`.** D-15's phases, their order and the interview's verbatim
  record all still bind. This entry narrows what the interview may carry, without switching any
  part of D-15 off.
- **Corrects:** D-15 — its interview phase: what the interview may ask, and what it may carry from
  the precondition checks.
- **Affects:** the `project-onboard` skill (0. PRECONDITIONS, step 2; 1. INTERVIEW, the new "Ask
  from §0 and this skill alone" rule and adoption question 1; HARD RULES, the first rule and a new
  rule beneath it); `decisions.d/2026-10-05-15.md`; #86.
