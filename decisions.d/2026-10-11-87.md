# D-87 — 2026-10-11 — Move the workflow rules into the plugin, and vendor the skills for cloud sessions

- **Decision:** Make the plugin the only authority for its rules, and reach every surface the
  plugin cannot reach by vendoring. The approved plan is `docs/plans/rules-in-the-plugin.md`. The
  design has four parts.
  1. **The `workflow` skill.** A new skill at `plugins/hivion/skills/workflow/` holds every rule
     `CLAUDE.md` holds today, the new-project interview, and the house style from `STYLE.md`. Every
     other skill cites it by name and by section heading, never by `§N` and never by path.
  2. **The `SessionStart` hook and its core.** A plugin hook prints `plugins/hivion/hooks/core.md`
     at every session start. The core holds eight rules that must hold unprompted, in 4,000
     characters or fewer. Its last line tells the agent to load the `workflow` skill before any
     ticket, branch, pull request, review or merge.
  3. **The vendor script.** `plugins/hivion/scripts/hivion-vendor.sh install <tag>` copies a
     release's skills into a consuming repository's `.claude/skills/`. It copies the core into
     `.claude/rules/hivion-core.md`, and writes a version marker at `.claude/hivion-version`. Its
     `check` mode reports drift from that release.
  4. **The route per surface.** A local session gets the skills from the plugin and the core from
     its hook. A cloud session and a routine get both from the vendored, committed copies. Cowork
     gets the skills enabled on the claude.ai account, and gets no core.

  The frozen contracts K1–K5 are in the plan's "Contracts" section: the skill's identity, the
  citation form and section map, the hook, the core text, and the vendor script. Changing one needs
  a new entry that `Supersedes` or `Corrects` this one.
- **Context:** #17 and #18, planned together on the owner's direction of 2026-10-04. The owner
  approved the plan on 2026-10-10 ("approve the plan"). The plan rejected these alternatives:
  - Shape 2, each skill carries the rules it enforces — eight copies of the merge gate would drift.
  - Shape 3, shared files cited by `${CLAUDE_PLUGIN_ROOT}` — the path does not resolve outside a plugin.
  - Inject the whole workflow through the hook — 55,543 characters against a 10,000-character cap.
  - Keep `CLAUDE.md` full and generate the skill from it — two copies of every rule, and a generator.
  - Cloud route 3, a `SessionStart` hook that fetches the skills — same-session discovery is undocumented.
  - Cloud route 4, a cloud environment setup script — per environment, not per repository.
  - Cloud route 2 alone, claude.ai account skills — per person, unversioned, invisible to the repository.
  - Vendor the whole `plugins/hivion/` tree — the hook, manifest and scripts have no consumer there.
  - Rewrite all eight skills in one unit — 13 files cannot share a wave, and exceed the check bound.
- **Affects:** #17, #18, #14, #19; this plan's issues #87, #88, #89, #90, #91, #92, #93, #94, #95
  and #96; `docs/plans/rules-in-the-plugin.md`.
