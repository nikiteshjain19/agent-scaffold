# D-15 — 2026-10-05 — Adopt an existing project through the `project-onboard` skill, interview first

- **Decision:** The scaffold gains an eighth skill, the `project-onboard` skill, for adopting the
  workflow into a project that already has code, a backlog, tests or a pipeline. It runs three
  phases in a fixed order: interview the owner and record every answer verbatim before reading any
  code; survey the repository, reusing the `project-audit` skill for the codebase and proving every
  fact with a command; reconcile the two in one table whose verdicts are Confirmed, Contradicted,
  Unverifiable and Unclaimed — and then stop, writing no `PROJECT.md` until the owner has answered
  the gaps. The skill carries six adoption rules: adopt forward and never backfill; never invent a
  value for a field; spec the existing backlog on pickup, never in bulk; let pull requests opened
  before adoption land under the old rules or close; report a committed secret without printing it;
  start the decision log now and never infer an earlier decision from code. Adoption ends in observe
  mode, and the generated `PROJECT.md` states what must hold before the auto lane is enabled. The
  owner chose the name on 2026-10-04, over `adopt`, `project-intake`, `project-reconcile`,
  `brownfield-setup` and `scaffold-retrofit`. It pairs with the `project-audit` skill, which it
  reuses for the survey. A plugin install lists it as `hivion:project-onboard`.
- **Context:** #15. `CLAUDE.md` §0 assumes a fresh repository: it asks what "done" looks like for
  v1 and tells the agent to create initial milestones and tickets. Run against a project that is
  halfway built, it produces a `PROJECT.md` describing an intention rather than the repository, and
  every later agent trusts that document. #16 routes §0 to this skill; that routing is not part of
  this decision.

  **Why the interview comes first.** A survey run first shapes the questions, and the owner ends up
  confirming what the code already does instead of stating what they want. The `project-audit` skill
  already holds the mirror-image rule — a reviewer primed with the spec confirms it rather than
  discovering the truth. The order is therefore the design: the owner's claims are captured
  unprimed, and only then tested. Recording them verbatim matters because a summary is already an
  interpretation, and the reconciliation table has to be able to quote the owner exactly when a
  verdict is Contradicted.

  **Why the survey runs in a subagent that has not seen the interview.** This is a judgment call the
  issue left open. Interview-first protects the owner from being primed by the code; it does nothing
  to protect the surveyor from being primed by the owner. An agent that holds the answers reads the
  repository to confirm them, which is the same failure in the other direction. Handing the survey
  to an agent that never saw the record closes both directions at the cost of one dispatch. Where a
  session cannot dispatch one, the skill runs the survey itself and says so, rather than refusing.

  **Why observe mode is written as a `*` entry at the top of the risk list.** The issue requires
  that a human merge everything after adoption, but no skill reads an "observe mode" field, and
  adding one would mean changing the `pr-merge-loop`, `pr-reviewer` and `cycle-manager` skills
  outside this issue's footprint. A `*` risk-list entry matches every path, so escalation
  condition 1 fires on every pull request through machinery every skill already honours. Removing
  it is a `PROJECT.md` edit, which is itself risk-listed, so leaving observe mode goes through a
  ticket, a pull request, a human and a decision entry. The alternative — declaring no green
  signal — was rejected because it would discard a real check the project may already trust, and
  conflate "no check exists" with "nobody has watched the check yet".

  **Why the backlog is held back with a declared hold signal.** The `issue-loop` skill filters out
  any issue carrying a hold signal `PROJECT.md` declares, and filters on nothing else. A
  pre-adoption signal (a `needs-spec` label, say) therefore makes the old backlog not loop-eligible
  with no change to the loop. An issue with no declared footprint is otherwise still eligible as a
  solo wave, so leaving the backlog unmarked would let the loop pick up issues no one has specced.
  Applying a label is a tracker write, so the skill applies it only after the owner agrees.

  **Why the "predate the gate" rule carries no count.** #15's backlog review asked for the rule to
  be written without a count, because #12 added an eighth escalation condition after #15 was filed.
  The rule now names `CLAUDE.md` §6's escalation conditions without numbering them, so it survives
  the next addition too.

  **Why the fail-closed defaults are a table in the skill.** "Never invent a value" is only
  checkable if the default for every field is written down in advance. The defaults follow the
  existing skills where they already state one — the `cycle-manager` skill's one cycle and zero
  repair rounds, `CLAUDE.md` §6's undeclared size threshold — and pick the conservative value where
  none exists: footprint enforcement on, enforcement "honoured only", no observe-mode exit until
  the owner states a period. The lane budget is the one deliberate departure. The `issue-loop`
  skill already defaults an undeclared lane budget to 3, but this skill writes 1 for a newly
  adopted project: one issue at a time is the more conservative choice while the owner has not
  yet watched the loop run. Each is written into the generated `PROJECT.md` as a default, so a
  reader can tell a chosen value from an unresolved one.

  **What was left alone.** `CLAUDE.md` needed no change: it lists no skills and states no skill
  count, and routing §0 to this skill is #16. The `cycle-manager` skill lists only the three skills
  it composes, and this one is not composed by it, so it was not falsified.
- **Affects:** the new `project-onboard` skill; `README.md` ("What's here" and "Use the workflow");
  `PROJECT.md` ("Product"); `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`
  (their descriptions); #15; #16, which routes `CLAUDE.md` §0 to this skill.
- **Corrected by:** D-67 — the adoption rules on the held backlog, open pull requests and
  committed secrets, and the fail-closed defaults.
