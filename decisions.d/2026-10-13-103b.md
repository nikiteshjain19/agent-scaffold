# D-103b — 2026-10-13 — Multica is the dispatch surface; GitHub Issues stays the tracker

- **Decision:** GitHub Issues remains the authoritative tracker for this repository, and "ticket"
  means a GitHub issue here. The Multica workspace that dispatches agents is not a second tracker.
  A Multica issue exists only to start and record an agent run; it names the GitHub issue it is
  working as `#N`; the status of the work lives on the GitHub issue; and neither system is mirrored
  into the other. `PROJECT.md`, "Toolchain" → "Multica dispatch surface", records it. Nothing in
  "Tracker mapping" changed.
- **Context:** #103. The owner stated this on 2026-10-13, in his own words: "**GitHub Issues remains
  the authoritative tracker for `agent-scaffold`.** … **Multica is the dispatch surface only.** A
  Multica issue exists to start and record an agent run. It is not a ticket, it does not carry
  status for the work, and it never replaces the GitHub issue." He added that the 14 open GitHub
  issues stay where they are, with their labels and dependency text intact, and that nothing is
  migrated, archived or refiled.

  **Why it has to be in the repository.** `git grep -il multica` over all 66 tracked files returned
  no match, so the rule lived only in a Multica comment thread. Every agent instance here starts
  with no memory of any earlier run and reads `PROJECT.md` cold. An agent that cannot find this rule
  reaches for the failure it prohibits: opening a GitHub issue to mirror a dispatch issue, or
  treating the dispatch issue as the ticket and leaving the GitHub status to rot.

  **Why `PROJECT.md` and not `CLAUDE.md` or a skill.** `PROJECT.md`'s "Constraints & working style"
  keeps the scaffold generic — project-specific facts live in `PROJECT.md`, never in `CLAUDE.md` or
  a skill. Which dispatcher drives this one repository is as project-specific as a fact gets, and
  `CLAUDE.md` travels to every consuming repository.

  **An earlier contrary instruction does not apply.** A comment on the Multica issue of 2026-10-13
  at 10:15Z declared Multica the only tracker and told agents never to create a GitHub issue. It did
  not come from the owner. He withdrew it in the same thread — "Mika's withdrawn comment of 10:15Z
  does not apply. This comment supersedes it." — before any document was written from it. Nothing
  in this repository was ever changed under it, so there is no earlier entry to supersede.
- **Affects:** `PROJECT.md` ("Toolchain" → "Multica dispatch surface"); #103.
