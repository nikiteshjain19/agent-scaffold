# D-12 — 2026-10-04 — An eighth escalation condition for irreversible effects, and a default risk list

- **Decision:** `CLAUDE.md` §6 gains an eighth escalation condition: the diff can cause an effect a
  revert cannot undo. The test is whether a revert of the commit returns the system to its prior
  state with no action outside the repository. It names five shapes — data deleted or an
  irreversible migration, a message sent to a person, money moved or spend incurred, a credential
  rotated or published, an external resource destroyed. Condition 4 now names the two common ways a
  test is weakened: a snapshot or expected-output fixture updated to match new output, and a
  threshold, tolerance or timeout loosened. §0 topic 7 now proposes a default risk list in two parts
  — files every project always protects (`CLAUDE.md`, `PROJECT.md`, `README.md`, the decision log,
  agent configuration, CI and deployment configuration) and a worked example of categories a project
  protects when it has them. It states that documentation outside the list is an ordinary change
  eligible for the auto lane, that classification reads the path rather than the PR's description,
  and that a project names its load-bearing documentation.
- **Context:** A risk-tiering policy written for a team was compared against §6 on 2026-10-03, and
  #12 took the gaps worth closing for a one-person project.

  **Why irreversibility is its own condition, and not a widening of condition 1.** Condition 1 asks
  *where* a change lands; the new condition asks *what a revert can undo*. Before this, an
  irreversible change escalated only if the project happened to have risk-listed its path, so the
  most expensive class of mistake depended on a list being complete. A list is enumerated in advance
  and by location; a code path that starts sending email, or calls a paid API, can appear in any file
  — a helper, a job, a handler nobody thought to list. Folding the shapes into the risk list would
  have meant guessing every such file ahead of time, and a guess that misses one is exactly the gap.
  Reading the effect from the diff closes it regardless of path. The condition is appended as 8
  rather than inserted, so every existing citation of conditions 1–7 keeps its meaning.

  **Why a legitimate snapshot update still fires condition 4.** #12 asks for an honest exception — a
  snapshot update is fine when the output changed on purpose and the PR says so — and also says it is
  "a finding to be explained, never an edit to be waved through". Whether the new output is correct
  is a judgment, not a predicate an agent can check, and §6 resolves what cannot be evaluated as
  met. So the exception is that such an update is permitted to merge, not that it skips a human: the
  condition fires, and the human reads the explanation the PR body gives.

  **Why the default risk list, and why no new condition for documentation.** The owner's direction
  (2026-10-03, on #12) is that a documentation change goes through the auto lane unless it edits
  `CLAUDE.md`, `PROJECT.md` or `README.md`. Condition 1 already fires only on risk-listed paths, so
  what was missing was the instruction that produces a sane list. Without one, a project either lets
  an agent rewrite its own merge rules unattended, or copies this repository's governance-heavy list
  and sends every typo to a human.

  **Count.** §6, the `pr-reviewer`, `pr-merge-loop` and `cycle-manager` skills now say eight. The
  repair block's "the other six escalation conditions are untouched" — which #10 item 2 reports as a
  miscount — was rewritten count-free ("no escalation condition is relaxed") rather than bumped to a
  number that would also be wrong. This change followed `main` as it stood at 4fd3f18; #10 had not
  landed.
- **Affects:** `CLAUDE.md` §0 topic 7 and §6 (conditions 4 and 8, the never-repairable list, the
  repair block, the auto-merge tier); the `pr-reviewer` skill (its conditions section and verdict
  block); the `pr-merge-loop` skill (its description, lanes, CLASSIFY conditions, the never-repair
  table and the hard rules); the `cycle-manager` skill; #10, #11, #15, #16, which touch the same
  passages.
- **Corrected by:** D-27 — the default list's "always risk-listed" part no longer names the decision
  log directory as a whole. It names a modified or deleted entry, and never an added one.
