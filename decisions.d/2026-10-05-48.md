# D-48 — 2026-10-05 — The `hivion` plugin installs from `plugins/hivion/`, not the repository root

- **Decision:** The `hivion` plugin's root is `plugins/hivion/`. It holds the manifest at
  `plugins/hivion/.claude-plugin/plugin.json` and the eight skills under `plugins/hivion/skills/`,
  moved there unchanged. The marketplace stays at the repository root, and its one entry's `source`
  is `./plugins/hivion`. Nothing else in the repository is part of the plugin. `package.json`,
  `package-lock.json`, `.markdownlint-cli2.yaml`, `.github/` and `.gitignore` stay at the root,
  where the green signal needs them (D-3). `PROJECT.md`, "Merge gate" → "Risk-list paths", lists
  `plugins/**` in place of `skills/**`, so every moved file stays risk-listed.
- **Context:** #48. With `"source": "./"` the whole repository root was the plugin, and Claude Code
  copies a plugin's directory into each consumer's plugin cache. The owner's position, on
  2026-10-05: "Yeah, I don't think the plugin should install from root and also include package
  JSON."

  **What an install of `main` actually received.** On 2026-10-05, Claude Code CLI 2.1.283 installed
  `main` at `7f3deef` into a throwaway configuration directory. The cached copy held every root file:
  `CLAUDE.md`, `STYLE.md`, `PROJECT.md`, `README.md`, `LICENSE`, `decisions.d/`, `.github/`,
  `.gitignore`, `.markdownlint-cli2.yaml`, `package.json` and `package-lock.json`. It also held a
  `node_modules/` with 81 top-level packages, `markdownlint-cli2` among them. That settles the
  question the documentation left open: the automatic dependency install does install a dependency
  declared only under `devDependencies`. `.git/` was not copied. The same install of this change's
  pushed branch held `.claude-plugin/` and `skills/` only, with no `node_modules/`, and
  `claude plugin details` listed all eight skills.

  **What stayed unverified.** How a symlink behaves on a local-path marketplace or on a Windows
  checkout was not tested, because the chosen layout has no symlink. No consumer machine was
  inspected, so the claim that consumers who installed after PR #24 hold `package.json` rests on the
  documented cache behaviour and on the install above, not on a consumer's cache.

  **Alternatives rejected.**
  1. **A symlink, `plugins/hivion/skills` pointing at the root `skills/`.** No skill file would
     move. The documentation says a symlink to a directory elsewhere in the same marketplace is
     dereferenced into the cache. Its behaviour on a local-path marketplace is unverified. Git on a
     Windows checkout without symlink support writes the link as a one-line text file, and the
     plugin then has no skills. A plugin that installs on some machines and silently loses its
     skills on others is worse than one rename of eight files.
  2. **A `git-subdir` source pointing at this same repository.** The documentation reserves it for a
     subdirectory of some other repository, and offers the relative path for the marketplace's own
     repository. It would also clone the repository a second time, at a ref the marketplace does not
     control.
  3. **Keeping `"source": "./"` and listing `skills` in the marketplace entry.** That limits which
     skills load, but the root is still the plugin. The copy and the dependency install are
     unchanged, so it fixes neither problem.
  4. **Moving the lint tooling out of the root instead.** The green signal runs `npm ci` and
     `npm run lint` from the root (D-3), and the issue puts relocating it out of scope. It would
     also leave `CLAUDE.md`, `PROJECT.md`, `decisions.d/` and the rest in every consumer's cache.

  **The risk-list repair.** The list is matched as `gitignore(5)` rules, and a pattern with a slash
  is anchored to the repository root. `skills/**` matches no file under `plugins/`, so a move that
  left the list alone would have taken every skill and the plugin manifest off it without a word.
  `plugins/**` covers the manifest and every skill, and any later plugin directory too. The
  coverage check in #48's Verification reports all nine tracked files under `plugins/` as matched.
  `.claude-plugin/**` stays, because it still covers `marketplace.json`.
- **Breaking or not:** Not breaking, under #4's definition. No `PROJECT.md` section the skills read
  by name is renamed, no skill is renamed, and the plugin and the marketplace keep the name
  `hivion`. The commands a consumer types are unchanged, and the skills still load as
  `hivion:<name>`. So the change forces no major version, and `version` stays `0.1.0` here; #47 owns
  the bump. Two effects are visible to a consumer. The cached copy no longer carries `CLAUDE.md`,
  `STYLE.md`, `PROJECT.md`, `README.md`, `LICENSE`, `decisions.d/` or the lint tooling, and the
  automatic dependency install no longer runs. A consumer who already holds `0.1.0` keeps the old
  copy until `version` is bumped, because the cache is keyed by version.
- **Corrects:** D-1. Its Decision records that this repository "holds `CLAUDE.md`, `STYLE.md` and
  the seven skills, and publishes them as one Claude Code plugin". The plugin no longer contains
  `CLAUDE.md` or `STYLE.md`, so that recorded fact is false. D-1's decision still binds: this public
  repository publishes the `hivion` plugin from a marketplace of the same name at its own root.
- **Affects:** `.claude-plugin/marketplace.json` (the `hivion` entry's `source`);
  `plugins/hivion/.claude-plugin/plugin.json` and `plugins/hivion/skills/<name>/SKILL.md`, all
  eight, at their new paths; `PROJECT.md` ("Product" → the "Purpose" line; "Merge gate" →
  "Risk-list paths"); `README.md` ("What's here", the skills bullet); D-1
  (`decisions.d/2026-09-23-1.md`); #47; #4; #48.
