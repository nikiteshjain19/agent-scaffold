# D-1 — 2026-09-23 — The scaffold is published here, as the `hivion` plugin

- **Decision:** This public repository is the live copy of the workflow scaffold. It holds
  `CLAUDE.md`, `STYLE.md` and the seven skills, and publishes them as one Claude Code plugin named
  `hivion`, from a marketplace of the same name at its own root. A consuming repository enables
  `hivion@hivion` in its `.claude/settings.json`, and its **local** sessions then load the skills.
  The skills are no longer symlinked into a personal skills directory. The private
  repository the scaffold grew in keeps its history, its decision log, its issues and its tooling
  (`scripts/`, `.githooks/`, CI, `tests/`), and stays private as a read-only backup. Its files were
  copied here, not moved, and its `main` was left unchanged.
- **Context:** A personal skills directory is read by local sessions only, and a symlink into it
  reaches no other machine, so every repository drifted or went without. A plugin fixes that for a
  local session: one versioned source, declared per repository, with no symlink to maintain.
  **It does not fix cloud sessions, and the decision was taken believing it would.** The
  correction, and what it costs, are recorded in the section below. Publishing the
  original repository was rejected, because that would expose its whole history, its decision log
  and every issue thread. A fresh public repository publishes only the files chosen for it.
  Before the copy, a read of every file found no personal, private or secret content, and five
  passages that were wrong or misleading outside their original repository. All five were fixed
  before the first push, so no draft of them is public. The tooling was left behind under the scope
  test in `PROJECT.md`: nothing here consumes it, and a consuming project implements its own.
  Plugin skills are always namespaced, so the skills are invoked as `hivion:<skill>`.
- **Affects:** the whole repository; every repository that installs the plugin; `README.md`, which
  carries the install snippet.

## Open, and not decided here

- **A cloud session installs no plugin a repository declares.** This was checked against the
  Claude Code documentation on 2026-10-03, after this entry was written: a cloud session does not
  install the plugins a repository turns on under `enabledPlugins`, including ones from the
  marketplaces it lists under `extraKnownMarketplaces`. So the plugin covers local sessions alone,
  and the gap this move was meant to close is still open for cloud sessions, Cowork and routines.

  What a cloud session does load is the clone — the repository's own `CLAUDE.md`, `.claude/rules/`,
  `.claude/skills/` and `.claude/settings.json` hooks — plus the skills enabled on the owner's
  claude.ai account. Each of those is a route, and each has a cost: a committed copy drifts, and an
  account-level install is per person rather than per repository. Choosing between them is a
  separate decision, and it is not taken here.

  **The move still pays for itself.** It removed the symlinks, gave the skills one versioned
  source, made them installable by anyone, and made the repository public — which is what lets a
  cloud session fetch from it at all.
- **`CLAUDE.md` does not travel with the plugin.** A plugin installs skills, not a workflow file, so
  a consuming repository copies or imports it. A home-directory import does not resolve in a cloud
  session. A committed `CLAUDE.md` does, because it is part of the clone. `README.md` states both
  routes and their limit.
- **No check runs on a pull request here.** Until one does, `CLAUDE.md` §0 leaves this project with
  no auto-merge tier, and every pull request waits for a human.
