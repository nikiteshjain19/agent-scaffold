# D-21 — 2026-10-04 — A run may execute up to five cycles

- **Decision:** `PROJECT.md`, "Merge gate" → "Parallelism", raises **Max cycles per run** from 3 to
  5. The lane cap (3) and the repair-round cap per pull request (3) stay as they are.
- **Context:** The owner asked for this on 2026-10-04, so that one session works more of the
  backlog before it stops. The `cycle-manager` skill reads its cycle cap from that section, offers
  no per-run override, and forbids exceeding the declared cap, so the number had to change in
  `PROJECT.md`.

  **The trade-off, stated plainly.** The cap is what stops a run that keeps opening pull requests
  which never merge (the `cycle-manager` skill's ASSESS phase). Raising it lengthens that worst case
  from three cycles to five. This project also has no green signal yet, so `CLAUDE.md` §0 leaves it
  no auto-merge tier, and every pull request waits for a human. Until a check exists, the extra
  cycles mostly add more open pull requests awaiting approval, not more merged work.
- **Affects:** `PROJECT.md` ("Merge gate" → "Parallelism"); the `cycle-manager` skill's CONFIG
  reading of the cycle cap; #21.
- **Corrected by:** D-3 — the Context sentence "This project also has no green signal yet" is no
  longer true: the `Markdown lint` job has been the green signal since PR #24 merged.
- **Superseded by:** D-35 — the lane cap only; the cycle cap still binds
