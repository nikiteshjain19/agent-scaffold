# D-78 — 2026-10-07 — The check environment hides the host login, fetches in the ordinary shell, and runs in one session

- **Decision:** Four corrections change the check environment that `pr-reviewer` §3 defines and that
  `project-audit` and `project-onboard` copy.
  1. **The environment hides the host CLI's login. It does not remove it.** The empty
     `GH_CONFIG_DIR` points `gh` away from its default configuration directory and its keyring
     entry, and both stay on disk. Every copy says "hides", and the `pr-reviewer` HARD RULES name
     the residual reach: code under test that resets `GH_CONFIG_DIR`, or reads those files
     directly, can still reach the host login.
  2. **Step 1 of `pr-reviewer` §3, `git fetch origin`, runs in the ordinary shell.** Every command
     from step 2 on, and check 4's run on the merged tree, stays in the check environment.
  3. **The worktree template is `mktemp -d "${TMPDIR:-/tmp}/wt-review-<n>.XXXXXX"`.** GNU
     coreutils `mktemp` rejects a template with fewer than three trailing `X`s, and BSD `mktemp`
     accepts both forms.
  4. **Each check runs in one quoted-heredoc session, not in a `sh -c '<command>'` form.** The
     session holds the worktree, the pre-PR gate, check 4's merge and merged-tree gate when BASE
     moved, and the removal, in order. A quoted heredoc passes a command with a single quote
     unchanged, and `$WT` set in the session reaches every later command. No copy keeps the
     `sh -c` form.
- **Context:** #78, from the review of PR #72 (D-62). That review found four defects in the
  check-environment text. The text said the environment removes the host login, but it only hides
  it. Its worktree template fails on GNU `mktemp`, so every Linux review escalated at worktree
  creation. Its fetch used the same credentials the check environment removes, so every review of a
  private or SSH remote escalated too. Its `sh -c '<command>'` form lost `$WT` between commands and
  broke on a single quote. The `project-audit` skill (D-65) and the `project-onboard` skill (D-67)
  copy the environment, so the false claim and the defects travelled with them.

  **Why "hides".** `gh` can keep its token in the system keyring, so an empty `GH_CONFIG_DIR`
  hides the login without deleting it. Calling that removal would tell the reader the host login
  is gone, and the reader would stop checking the residual reach. The sentence now states what the
  environment does and what it leaves on disk.

  **Why step 1 runs outside the environment.** Step 1 runs no code from the pull request. §0 step 3
  already fetches with the same credentials, so the fetch exposes nothing new. Inside the
  environment, the fetch failed for any private or SSH remote, and the review escalated before it
  checked anything.

  **Why one session.** Each `sh -c` started a shell that lost the variables the previous command
  set, so `$WT` was empty after the first command. A quoted heredoc sends the commands to one
  shell without expansion by the outer shell, so a single quote in a command breaks nothing.

  **Why the template has three `X`s.** The GNU manual requires at least three consecutive `X`s in
  the last component of the template, and the old `-t wt-review-<n>` form gave none.

  **Corrects, not supersedes.** D-62 item 5 still binds: the checks still run without the host
  login, and the skill still says it is not a sandbox. Only its mechanism and its wording change.
  D-62's own Context already says the empty `GH_CONFIG_DIR` "hides" the token, so this entry
  brings the instruction text in line with that record. D-65 and D-67 cite "the credential-free
  environment #62 defines" by reference and restate none of the corrected claims, so this entry
  writes no relation to them.
- **Corrects:** D-62 — item 5, the check environment. D-62 still binds, and this entry changes how
  its item 5 was recorded and its mechanism.
