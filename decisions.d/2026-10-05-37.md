# D-37 — 2026-10-05 — A shape outweighs a caller or a test, an explicit ask outweighs a shape, and R3 repairs an unjustified line

- **Decision:** A line that matches a shape in `CLAUDE.md` §4, "Justify every line you write", has
  no reason, unless the acceptance criteria name it explicitly. An existing caller or a test never
  outweighs a shape. An unjustified line is an R3 repair in the `pr-merge-loop` skill: the merge
  flow removes it, and inlines a helper with one caller into that caller. The merge flow never
  removes a line the acceptance criteria name explicitly.
- **Context:** #37, filed from the review of PR #33, which shipped D-11. That review found two
  gaps, and the owner approved PR #33 knowing about both.

  **The merge flow could not see that an unjustified line is repairable.** The `pr-merge-loop`
  skill's R3 read "a bug, an unchecked silent-failure result, or a missing error path". D-11's
  **Affects** field claimed R3 "now includes an unjustified line", but no text said so. A merge flow
  that read R3's examples as complete escalated the finding instead of removing the line.

  **A reason and a shape could both fit one line.** The reason "an existing caller needs it" pulls
  against shape 3, "a helper, parameter, option or config key with one caller, or none": a
  one-caller helper has a caller that needs it. The reason "a test covers it" pulls the same way
  when the helper is tested. The block asserted that the shapes "have none", but never said which
  side wins when both seem to fit. D-11's Decision already read the shapes as having no reason, so
  the shape wins over a caller or a test. This entry makes the text of `CLAUDE.md` §4 and of R3 say
  what D-11 already meant.

  **Why an explicit ask beats a shape.** The owner ruled on 2026-10-05: "I agree. Requirement
  wins." Without that exception, an option the acceptance criteria require, read in one place,
  matches shape 3, and the R3 repair would delete requested work. Limiting the exception to an
  explicit ask keeps the rule's teeth: a one-use helper that merely has a caller or a test is still
  caught, because neither of those reasons outweighs a shape.

  **Why `Corrects`, not `Supersedes`.** D-11 still binds: every line still needs a reason, and the
  seven shapes still have none. This entry changes how D-11 is stated and where its repair is
  written down, not whether it applies. That is the `CLAUDE.md` §7 test for `Corrects`.

  **Why the `pr-reviewer` skill carries the same exception.** Its check 1 records `fail` on any
  line that matches a shape, and it skips only the exemptions it lists. The first draft of this
  change left that list alone, on the premise that the precedence question could not arise there.
  The independent review of PR #56 found the premise wrong: a reviewer reading that list would
  still reject a line the acceptance criteria name explicitly. That defeats the exception at review
  time, before the merge flow ever reaches R3. The owner widened #37's footprint on 2026-10-05 to
  fix it, and the list now names that line as an exemption.
- **Corrects:** D-11.
- **Affects:** `CLAUDE.md` §4, "Justify every line you write"; the `pr-merge-loop` skill, REPAIR,
  R3; the `pr-reviewer` skill, check 1; `decisions.d/2026-10-05-11.md` (D-11); #11; PR #33; #37.
