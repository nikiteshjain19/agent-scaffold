# D-103 — 2026-10-13 — The checker's rule configuration is risk-listed, beside the tooling that runs it

- **Decision:** `.markdownlint-cli2.yaml` joins the risk-list paths in `PROJECT.md`, "Merge gate" →
  "Risk-list paths". The paragraph that explains why the dependency manifests are listed now covers
  all three entries, and separates the lint *tooling*, pinned in `package.json`, from the lint
  *rules*, held in `.markdownlint-cli2.yaml`. No other pattern changed.
- **Context:** #103, from the owner's onboarding review of this repository. Resolving all 66 tracked
  files against the declared list with its own matcher —
  `git -c core.excludesFile=<list> check-ignore --no-index --stdin --non-matching` — returned four
  paths outside it: `.gitignore`, `.markdownlint-cli2.yaml`, `CHANGELOG.md` and
  `docs/plans/rules-in-the-plugin.md`. One of those four configures the only check this repository
  has.

  **The gap this closes.** A PR that disables one markdownlint rule tripped no escalation condition
  that reads a path. Condition 1 found no risk-list match. The green signal reported success,
  because the lint job runs with the edited configuration. One file and one line sit far inside the
  50-line / 3-file size threshold, so condition 5 stayed quiet. The PR could therefore reach the
  auto-merge tier having narrowed the gate that admitted it.

  **Why condition 4 was not enough.** `CLAUDE.md` §6, condition 4, fires on a test deleted, skipped
  or weakened, and names two weakening shapes: a fixture updated to match new output, and a
  loosened threshold, tolerance or timeout. A disabled lint rule is neither, and `PROJECT.md`
  declares **Test: none** for this repository. Condition 4 therefore asked a merging agent to
  decide that a YAML edit weakens a test in a project that states it has no tests. Condition 1 reads
  a path and needs no such judgment, so the fix belongs in the risk list.

  **What this completes in D-3.** D-3's Context argued that an exact version pin plus a committed
  lockfile makes a change to the gate "show up as a change to `package.json` — a risk-listed path,
  which escalates under condition 1". That reasoning holds for the tooling and stops short of the
  rules, which live in a separate file at the root. This entry extends the same argument to the
  remaining gate input rather than revising it.

  **Why neither relation applies.** `CLAUDE.md` §7 asks whether the earlier decision still binds.
  D-3 still binds: the green signal is still the `Markdown lint` job on pinned tooling. D-45 still
  binds: `PROJECT.md` still declares the gate's inputs and predicts no outcome. Neither decided the
  risk list's contents, so neither is switched off or rescoped, and no earlier entry is edited.
  D-45's own Context sets this precedent, reaching the same conclusion for D-3, D-8 and D-35.

  **What was deliberately left out.** The owner reviewed all four unlisted paths on 2026-10-13 and
  chose this one alone. `CHANGELOG.md`, `docs/plans/**` and `.gitignore` stay off the list.
  `CLAUDE.md` §0's generic default risk list is also unchanged: it offers "CI and deployment
  configuration", and a checker's rule configuration need not sit under a CI directory, so every
  consuming repository inherits the same gap. Closing that affects every consumer and needs its own
  issue.
- **Affects:** `PROJECT.md` ("Merge gate" → "Risk-list paths"); `.markdownlint-cli2.yaml`; D-3;
  D-45; #103.
