# D-34 — 2026-10-06 — The cycle manager answers run-order questions itself

- **Decision:** The `cycle-manager` skill may answer a question when every option changes only
  which agent it dispatches next, or only when it dispatches that agent. It may not answer a
  question whose answer allows a merge, a write, a scope change or a cap change. A question it
  cannot classify goes to the user. The skill also states three rules: the merger dispatch order
  (a stacked parent first, then the smaller diff, then the lower pull-request number); one fresh
  reviewer for a reviewer that returns no C2 block; and the route for a repairer or merger that
  returns no block. Every answer the manager gives is recorded in a "Decided for you" table in the
  run report. `CLAUDE.md` §13 keeps asking as the default, and names the `cycle-manager` skill as
  the one exception. The question about the merger's closing ASK is not carried: since D-6, the
  `pr-merge-loop` skill's SINGLE-PR MODE prints no closing ASK.
- **Context:** The issue came from the owner in a Claude Code session on 2026-10-05. The user was
  the bottleneck for questions that only decide what the run does next. The wider version was
  rejected: letting the manager approve merges. The manager dispatches the builder and holds every
  report, so it is not independent, and such approval would replace the `CLAUDE.md` §6 predicates
  with judgment. The lane stopped on 2026-10-06, because one instruction ("Put it in the digest")
  conflicted with D-20 for a stopped merger. The owner chose to follow the merged rules, so the
  route for a stopped merger and a repairer with no block now follows D-20. This decision corrects
  nothing and supersedes nothing.
- **Affects:** #34; `plugins/hivion/skills/cycle-manager/SKILL.md` (a new RUN-ORDER QUESTIONS
  section, DRIVE step 3, DRIVE step 8, MERGE step 4, the carried-pull-request paragraph, HARD RULES,
  and the RUN REPORT); `CLAUDE.md` §13.
